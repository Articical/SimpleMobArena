# Paper 26.3 staging acceptance checklist

Run these on a staging copy using Java 25, the exact deployed Paper build, Vault, EssentialsX and your usual protection/teleport/inventory plugins. Keep production currency and player data separate. Record plugin versions, configuration, session IDs, console logs and before/after balances. Take a full backup before crash testing.

For inventory checks, use distinct named/enchanted items, damaged armor, offhand gear, XP, effects and nondefault food/health. Record every slot before joining and after leaving/recovery. Confirm no duplicate inventory, dropped items, unowned kit items or unexpected XP exist. Confirm console errors are absent or expected and clearly explained.

| Scenario | Procedure | Acceptance criteria |
| --- | --- | --- |
| Startup/configuration | Boot with missing/invalid worlds, out-of-bound spawns, unsupported mobs, overlapping arenas and malformed economy values; then fix and reload | Helpful errors; invalid arena cannot join/start; invalid economy suspends deposits; corrected idle config becomes usable |
| Arena setup and upgrade repair | Configure a new arena using corners at different Y heights, setplayer, setmob, addmob, setexit and setoutsider exit. Repeat using a 1.0.0 arena with stale sample spawns outside its new boundary. Inspect setup/status before and after repairs; restart and inspect again | New arenas have no sample coordinates. Set replaces all points of the chosen type; add appends; clearspawns only clears the requested type. Setup shows stored coordinates, Y bounds, spawn counts and actionable errors; valid repairs survive restart. Outsiders follow subsequent setexit changes when configured with setoutsider exit. Invalid enable reports a concise setup command |
| Setup permissions and occupied state | Grant only one setup action permission to a nonoperator; try each new command and tab completion. While a match is occupied, attempt replacement, append, clearing and switching the outsider exit | Permissions are checked before mutation; tab completion offers only permitted actions. All occupied arena edits are rejected with stored geometry and current session intact |
| Solo personal session | Join with personal gear; complete at least the minimum waves and participation time; end by elimination | One countdown, one wave spawn sequence; consumables/wear follow config; only completed waves earn pot; ledger and provider payment agree |
| Public lobby announcements and private countdown titles | Observe from outside the arena while players join a default lobby, fill it, and start; run a second arena at the same time. Keep legacy public.countdown true during upgrade | Public join/start/end messages identify the arena. Only participants see center-screen countdown titles at 15/10/5/3/2/1, then FIGHT! at actual start; no countdown chat or pause notice reaches outsiders or another arena. Join announcements offer a command suggestion when slots remain; full arenas do not. Participants receive one copy, outsiders with no join permission receive no invitation, and no click executes a command immediately |
| Countdown lifecycle | Use min-players 2, leave during countdown then rejoin, reserve equipment preparation at the deadline, manually start early, and test zero/nonstandard countdown durations | Countdown pause is private to participants, replacement begins a fresh full interval, and old deadlines do not cause start notices. No FIGHT! title/start cue before preparation finishes; no later countdowns after manual start/cancellation. Leaving a lobby clears its title. Initial nonstandard positive duration is shown once; zero emits only actual start. Empty idle arenas stay quiet during reload/shutdown |
| Credited kill sound and currency labels | Kill tracked mobs with melee/projectiles, compare another participant/outsider/environmental kill, and disable sounds.mob-kill.enabled. Inspect /ma top and /ma stats | Only the credited killer hears the quiet kill cue once per tracked death. Mount/unrelated mob deaths and noncredited kills do not trigger it. Disabling the cue suppresses only that sound. Earnings have a single $ prefix while amounts, ordering and confirmed-payment rules remain unchanged |
| Event sounds and controls | Listen inside and outside during join/countdown/start/waves/elimination/end/cancellation. Disable all sounds, then one cue, adjust sound/volume/pitch, and set public announcement toggles false; reload while idle | Only participants hear cues, with no doubled match-start/wave-one or final-wave/end cue. Departing player hears elimination once; other players keep playing. Config reload applies changes, private events stay inside, invalid values fall back with useful logs, and presentation failure does not stop cleanup or payment |
| Solo elimination and reward explanation | With defaults, complete only wave one ($100 pot) and be eliminated. Then use an eligible player with no active reward cooldown to complete at least three waves and play 60 seconds before elimination | Join explains three team waves, 60 seconds and credited kills; early wave messages show 1/3 and 2/3. Both defeats show ELIMINATED plus personal kills, damage, waves and time. The early defeat reports $0 with the three-wave requirement. The eligible defeat records a non-cancelled match, confirms the actual payment after it is saved, and changes the provider balance once |
| Personal results while others continue | Eliminate one player after they earn kills; keep another alive through further waves, then finish. Repeat with voluntary leave and a player who disconnects before payment | Departing player gets their own summary and clearly provisional estimate; survivor gets the elimination announcement. Recorded contributions remain. Online participants receive final status after the match; offline participants see the stored result in history on return. No title/chat error can block inventory recovery or create another deposit |
| Opening melee waves | Keep an old skeleton wave-1 configuration, including custom early witch/pillager/blaze/stray rules. Run waves one through three and inspect later unlocks | No ranged-capable mobs appear in waves one or two. Early ranged rules become eligible at wave three; later configured unlocks remain later. Source configuration is preserved. A configuration with no wave-one melee mob is rejected with an actionable error |
| Four-player session | Compare solo and four-player matches with defaults; eliminate/disconnect two players between spawn batches and continue into the next wave. Then start a new solo match | Wave one has 6 mobs solo or 9 with four starters; ordinary zombie health is 20 or 29 points respectively. Count and health continue using four starters after departures; the next solo match resets to solo scaling. Shares include earlier players' kills; no amount above pot/caps; rounding exact before deductions |
| Health scaling settings and caps | Test custom player-health-scaling values, disabled scaling, missing keys in an older config, and invalid types/ranges. Compare wave 5 with wave 6 and test high configured difficulty plus enough starting players to hit the multiplier cap | Missing keys use +15% per extra starter, capped at 2.5x. Disabling affects only the player health multiplier. Wave growth, mob multipliers and arena difficulty still apply; assigned max/current health never exceeds 1024. Invalid settings prevent joining with actionable validation errors. Count and active-mob caps continue to apply |
| Concurrent arenas | Run two disjoint physical arenas with different players | Independent counters, timers, IDs and cleanup; projectiles/damage cannot cross sessions; one finish does not clear the other's mobs |
| Disconnect in combat | Disconnect with personal gear, repeat with a class; finish the match while offline | Participant is removed once; contribution retained; no later kills; class snapshot restored on reconnect; original gear is not duplicated |
| Reconnect after elimination | Eliminate then disconnect during/after restoration; reconnect repeatedly and attempt to rejoin the active match and its intermission | Restore applied at most as a fenced exact replacement; once confirmed it is not reapplied; stats/payout not duplicated; joining remains rejected during ACTIVE and INTERMISSION |
| Voluntary leave | Leave midwave, repeat during countdown and immediately after join while snapshot is saving | No late eligibility or extra kill credit; countdown safely cancels below minimum; pending join cleans up; earned contribution remains for a started match |
| Lethal mob hit | Reduce health and take otherwise lethal melee/projectile damage; deliver multiple same-tick lethal hits if possible | Lethal damage cancelled; one elimination; no death screen, inventory/XP drops or duplicate settlement; safe exit and healed/fed state |
| Environmental lethal hit | Repeat with fall, fire, lava, drowning, suffocation, poison/wither combinations, freezing and void where possible | Same elimination behavior; surviving damage continues normally; no lingering damage immediately kills the recovered player |
| Personal equipment options | Test all combinations of preserve-durability and restore-consumables; shoot arrows, eat food, drink potions/milk and rearrange slots | Default consumables/wear remain spent; enabled preservation/refunds behave correctly; empty bottles/bowls/buckets cannot be duplicated |
| Class escape attempts | Try Q-drop, cursor items, hotbar swaps, shift/double clicks, inventory drag, crafting, containers, hoppers, bundles, armor stands, item frames and external inventory commands | No class or refunded personal items enter normal survival storage; normal inventory is intact after recovery |
| GUI and permissions | Use all menu pages, equipment choices, stats/refresh/leave; shift-click/drag/drop menu icons; revoke permissions with menu open | Menu items cannot move; holder/slot authorization holds; current permissions rechecked; no stale menu bypass; leave remains possible |
| Citizens menu NPC | With Citizens installed, create a named NPC outside enabled arenas, right-click it, select an arena and equipment, then complete a match. Bind a separate existing NPC, restart, and repeat. Unbind it and repeat | One normal arena GUI opens per click, existing selection/join guards remain effective, both NPCs and UUID bindings survive restart, and unbinding preserves the NPC without opening the MobArena menu |
| Citizens limits and recovery | Attempt NPC admin commands without permission; click without use/join permission, during participation and during equipment recovery; double-click and log out before the deferred GUI opens. Create/bind inside an enabled arena; simulate failed spawn or binding save; restart without Citizens; reuse a deleted NPC's numeric ID | Unauthorized operations do not mutate NPCs; restricted/deferred clicks cannot bypass state or permission checks. Duplicate clicks do not open stacked menus. Unsafe placement is refused. Failed creation leaves no newly created orphan NPC or active link. Missing Citizens leaves ordinary arena commands usable; reused numeric IDs never inherit a deleted NPC's UUID binding |
| Outsiders | Attack participants/mobs with melee, arrows, pets, potions and explosions; shoot from outside and across two arenas; enter by walking, teleport, login and mounted movement, including an operator account | Outsiders get no contribution and cannot damage participants/arena mobs; intruders are moved to the fixed safe outsider exit; arena entities do not damage ordinary SMP players |
| Escape | Walk/fly/pearl/chorus/portal/command-teleport out, move into another arena, try logout/relogin beyond boundary | Movement/teleport is blocked or participation ends safely; no contribution or paid combat from outside |
| Command isolation | During participation try non-arena inventory/teleport/economy commands, namespaced spellings, aliases and a different plugin claiming `/ma`; try MobArena admin actions as an operator participant | Nonmatch commands remain denied; command ownership is resolved rather than trusting text alone; safe MobArena player commands remain available; no alias or namespace bypass |
| Mob variety/daylight | Run enough waves for zombie gear variants, husks, skeletons and configured rare jockeys under an open midday sky. Include adult and baby zombies and skeletons; compare with ordinary survival undead. Separately test fire/lava contact and a flaming attack | Equipment weights/unlocks operate; owned undead take no sunlight fire damage, including after spawn setup and any pending sun ignition; ordinary undead retain normal behavior. Sunlight protection does not cancel block- or entity-caused ignition. Riders/mounts/equipment are fully cleaned up |
| Creeper and drowned exclusion | Keep old `waves.mobs.CREEPER` and `waves.mobs.DROWNED` entries with high weights and wave-1 unlocks, then reload while idle and run multiple waves. Leave an arena zombie submerged long enough to attempt conversion | Arena remains valid with another supported wave-1 mob; no arena creepers or drowned spawn; arena zombie conversion is cancelled; legacy settings remain untouched; WorldGuard protections remain enabled |
| Idle arena spawn protection | Try natural spawning, a spawner, spawn eggs, thrown eggs and another plugin's custom spawn inside an enabled arena before joining and during a match. Repeat outside its boundary and after disabling it. Run a normal wave with jockeys | Unrelated creature spawns are blocked in both idle and occupied enabled arenas; own current-session mobs and mounts spawn normally unless another plugin denies them. Stale or another arena's session tags do not bypass protection. Outside/disabled arena spawning and preexisting creatures remain unchanged |
| Structural protection | Trigger fireballs, enderman griefing and ranged attacks around arena blocks | Arena routine play changes no blocks; no surviving class/mob items or temporary entities; ordinary unrelated SMP behavior unaffected |
| Mob missing/stuck | Remove a tracked mob without death; attempt unload; block a spawn; allow timeout | Session cancels conservatively without payout, or tracked chunks remain loaded; no deadlocked rewarded wave; all survivors recover |
| Administrative controls | Start empty/invalid arena; stop active session; forcewave during active combat and intermission; reload/delete occupied arena | Invalid operations rejected; admin stop never pays; forcewave only shortens intermission; occupied state not silently discarded |
| Missing provider | Start without Vault, then without EssentialsX provider; finish eligible session; restore provider | Gameplay works; ledger remains pending with no deposit attempt; provider restoration pays eligible pending once subject to caps |
| Payout controls | Test session/player/daily caps, cooldown, minimum waves/time, short-session reduction, disabled payouts and zero credited kills | No cap exceeded; deductions never redistributed; zero kills no arbitrary payout; UTC reset/holds documented and correct |
| Class restart | Clean stop while class kit active; reconnect after restart; repeat abrupt termination before/after PREPARED, RESTORING, player save and CONFIRMED | Durable originals retained; safe restoration and quarantine where needed; no item duplication/loss; confirmed records not replayed |
| Settlement restart | Use a controlled test provider to halt before deposit, after deposit but before SQLite confirmation, and after confirmation | PENDING can progress; ambiguous PROCESSING becomes UNCERTAIN; no blind retry; CONFIRMED never redeposits |
| Reconciliation | Verify underlying provider audit, run CONFIRM or VOID on UNCERTAIN; repeat command and target wrong state | Exactly the recorded state changes; no Vault call; audit records operator/decision; repeated/wrong-state request rejected; caps remain conservative |
| Storage failure | Make a staging DB unavailable/full/corrupt at controlled snapshot and payout boundaries, then restore healthy backup | No unsnapshotted inventory clear; interaction paused with evidence retained; deposits suspended on ledger failure; no unsafe retry |
| MySQL backend | Run the same session, recovery and financial scenarios on a dedicated MySQL staging database; interrupt connectivity during writes | Schema, prepared statements, timestamps and money remain correct; no failed write bypasses safety; reconnect never blindly retries an uncertain deposit |
| Offline storage migration | Stop all writers; migrate SQLite to empty MySQL, then back to a separate empty SQLite directory; include confirmed/uncertain payments and unconfirmed snapshots | Table counts and SHA-256 readback verification pass; source rows remain intact; exact snapshot bytes and status preserved; occupied/same target refused; only the chosen copy is activated |
| Match reporting | Inspect `/ma history`, `/ma match` and the three reporting views for completed, cancelled, capped and uncertain sessions; rename a player between matches | Names are historical labels and UUID remains identity; complete roster persists; intended versus confirmed amounts are distinct; cancelled outcome and unallocated pot are correct |
| Optional integrations | Start with/without WorldGuard and PlaceholderAPI; set valid/missing/too-small regions; render each placeholder from main-thread and asynchronous consumers | Optional plugins absent do not prevent unconfigured gameplay; configured invalid region fails validation; placeholders use cached values without async world access; expected loading/staleness documented |
| WorldGuard spawn and combat flags | Deny mob spawning in an overlapping spawn region and start a match. Then follow the README's dedicated arena-region fix with higher priority and mob-spawning allow; repeat with an inherited deny-spawn list and an explicit empty override using `-e`. Test mob-damage deny/allow and chicken mounts with the arena permissions | Rejected waves cancel without payout, restore equipment and log useful diagnostics; the plugin never uncancels WorldGuard events. New matches spawn and mobs damage participants after the local flags permit them. Unsetting a deny list alone must not be mistaken for overriding inheritance. Surrounding spawn protection and arena block protection remain effective; block-plugin-spawning stays enabled |

For restart tests, a normal `stop` verifies graceful shutdown only. An abrupt process termination test is a separate requirement. Vault crash-boundary tests require a controlled provider/test harness that can pause a deposit at known points; merely restarting after a normal match does not validate uncertainty handling.

Before deployment, obtain passing evidence for every financial/inventory row and inspect the unchanged ordinary survival area below the arena. Remaining failures or untested critical rows block a production-ready claim.

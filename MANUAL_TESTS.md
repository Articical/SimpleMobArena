# Paper 26.3 staging acceptance checklist

Run these on a staging copy using Java 25, the exact deployed Paper build, Vault, EssentialsX and your usual protection/teleport/inventory plugins. Keep production currency and player data separate. Record plugin versions, configuration, session IDs, console logs and before/after balances. Take a full backup before crash testing.

For inventory checks, use distinct named/enchanted items, damaged armor, offhand gear, XP, effects and nondefault food/health. Record every slot before joining and after leaving/recovery. Confirm no duplicate inventory, dropped items, unowned kit items or unexpected XP exist. Confirm console errors are absent or expected and clearly explained.

| Scenario | Procedure | Acceptance criteria |
| --- | --- | --- |
| Startup/configuration | Boot with missing/invalid worlds, out-of-bound spawns, unsupported mobs, overlapping arenas and malformed economy values; then fix and reload | Helpful errors; invalid arena cannot join/start; invalid economy suspends deposits; corrected idle config becomes usable |
| Solo personal session | Join with personal gear; complete at least the minimum waves and participation time; end by elimination | One countdown, one wave spawn sequence; consumables/wear follow config; only completed waves earn pot; ledger and provider payment agree |
| Four-player session | Join four players; compare wave counts to solo; eliminate two, then finish | Difficulty continues using four starting players; shares include earlier players' kills; no amount above pot/caps; rounding exact before deductions |
| Concurrent arenas | Run two disjoint physical arenas with different players | Independent counters, timers, IDs and cleanup; projectiles/damage cannot cross sessions; one finish does not clear the other's mobs |
| Disconnect in combat | Disconnect with personal gear, repeat with a class; finish the match while offline | Participant is removed once; contribution retained; no later kills; class snapshot restored on reconnect; original gear is not duplicated |
| Reconnect after elimination | Eliminate then disconnect during/after restoration; reconnect repeatedly and attempt to rejoin the active match and its intermission | Restore applied at most as a fenced exact replacement; once confirmed it is not reapplied; stats/payout not duplicated; joining remains rejected during ACTIVE and INTERMISSION |
| Voluntary leave | Leave midwave, repeat during countdown and immediately after join while snapshot is saving | No late eligibility or extra kill credit; countdown safely cancels below minimum; pending join cleans up; earned contribution remains for a started match |
| Lethal mob hit | Reduce health and take otherwise lethal melee/projectile damage; deliver multiple same-tick lethal hits if possible | Lethal damage cancelled; one elimination; no death screen, inventory/XP drops or duplicate settlement; safe exit and healed/fed state |
| Environmental lethal hit | Repeat with fall, fire, lava, drowning, suffocation, poison/wither combinations, freezing and void where possible | Same elimination behavior; surviving damage continues normally; no lingering damage immediately kills the recovered player |
| Personal equipment options | Test all combinations of preserve-durability and restore-consumables; shoot arrows, eat food, drink potions/milk and rearrange slots | Default consumables/wear remain spent; enabled preservation/refunds behave correctly; empty bottles/bowls/buckets cannot be duplicated |
| Class escape attempts | Try Q-drop, cursor items, hotbar swaps, shift/double clicks, inventory drag, crafting, containers, hoppers, bundles, armor stands, item frames and external inventory commands | No class or refunded personal items enter normal survival storage; normal inventory is intact after recovery |
| GUI and permissions | Use all menu pages, equipment choices, stats/refresh/leave; shift-click/drag/drop menu icons; revoke permissions with menu open | Menu items cannot move; holder/slot authorization holds; current permissions rechecked; no stale menu bypass; leave remains possible |
| Outsiders | Attack participants/mobs with melee, arrows, pets, potions and explosions; shoot from outside and across two arenas; enter by walking, teleport, login and mounted movement, including an operator account | Outsiders get no contribution and cannot damage participants/arena mobs; intruders are moved to the fixed safe outsider exit; arena entities do not damage ordinary SMP players |
| Escape | Walk/fly/pearl/chorus/portal/command-teleport out, move into another arena, try logout/relogin beyond boundary | Movement/teleport is blocked or participation ends safely; no contribution or paid combat from outside |
| Command isolation | During participation try non-arena inventory/teleport/economy commands, namespaced spellings, aliases and a different plugin claiming `/ma`; try MobArena admin actions as an operator participant | Nonmatch commands remain denied; command ownership is resolved rather than trusting text alone; safe MobArena player commands remain available; no alias or namespace bypass |
| Mob variety/daylight | Run enough waves for zombie gear variants, skeletons, drowned and configured rare jockeys in daylight | Equipment weights/unlocks operate; no arena sunlight burning; normal survival undead still burn; riders/mounts/equipment are fully cleaned up |
| Structural protection | Trigger creeper explosions, fireballs, enderman griefing and ranged attacks around arena blocks | Arena routine play changes no blocks; no surviving class/mob items or temporary entities; ordinary unrelated SMP behavior unaffected |
| Mob missing/stuck | Remove a tracked mob without death; attempt unload; block a spawn; allow timeout | Session cancels conservatively without payout, or tracked chunks remain loaded; no deadlocked rewarded wave; all survivors recover |
| Administrative controls | Start empty/invalid arena; stop active session; forcewave during active combat and intermission; reload/delete occupied arena | Invalid operations rejected; admin stop never pays; forcewave only shortens intermission; occupied state not silently discarded |
| Missing provider | Start without Vault, then without EssentialsX provider; finish eligible session; restore provider | Gameplay works; ledger remains pending with no deposit attempt; provider restoration pays eligible pending once subject to caps |
| Payout controls | Test session/player/daily caps, cooldown, minimum waves/time, short-session reduction, disabled payouts and zero credited kills | No cap exceeded; deductions never redistributed; zero kills no arbitrary payout; UTC reset/holds documented and correct |
| Class restart | Clean stop while class kit active; reconnect after restart; repeat abrupt termination before/after PREPARED, RESTORING, player save and CONFIRMED | Durable originals retained; safe restoration and quarantine where needed; no item duplication/loss; confirmed records not replayed |
| Settlement restart | Use a controlled test provider to halt before deposit, after deposit but before SQLite confirmation, and after confirmation | PENDING can progress; ambiguous PROCESSING becomes UNCERTAIN; no blind retry; CONFIRMED never redeposits |
| Reconciliation | Verify underlying provider audit, run CONFIRM or VOID on UNCERTAIN; repeat command and target wrong state | Exactly the recorded state changes; no Vault call; audit records operator/decision; repeated/wrong-state request rejected; caps remain conservative |
| Storage failure | Make a staging DB unavailable/full/corrupt at controlled snapshot and payout boundaries, then restore healthy backup | No unsnapshotted inventory clear; interaction paused with evidence retained; deposits suspended on ledger failure; no unsafe retry |
| MySQL backend | Run the same session, recovery and financial scenarios on a dedicated MySQL staging database; interrupt connectivity during writes | Schema, prepared statements, timestamps and money remain correct; no failed write bypasses safety; reconnect never blindly retries an uncertain deposit |
| Offline storage migration | Stop all writers; migrate SQLite to empty MySQL, then back to a separate empty SQLite directory; include confirmed/uncertain payments and unconfirmed snapshots | Table counts and SHA-256 readback verification pass; source rows remain intact; exact snapshot bytes and status preserved; occupied/same target refused; only the chosen copy is activated |
| Match reporting | Inspect `/ma history`, `/ma match` and the three reporting views for completed, cancelled, capped and uncertain sessions; rename a player between matches | Names are historical labels and UUID remains identity; complete roster persists; intended versus confirmed amounts are distinct; cancelled outcome and unallocated pot are correct |
| Optional integrations | Start with/without WorldGuard and PlaceholderAPI; set valid/missing/too-small regions; render each placeholder from main-thread and asynchronous consumers | Optional plugins absent do not prevent unconfigured gameplay; configured invalid region fails validation; placeholders use cached values without async world access; expected loading/staleness documented |

For restart tests, a normal `stop` verifies graceful shutdown only. An abrupt process termination test is a separate requirement. Vault crash-boundary tests require a controlled provider/test harness that can pause a deposit at known points; merely restarting after a normal match does not validate uncertainty handling.

Before deployment, obtain passing evidence for every financial/inventory row and inspect the unchanged ordinary survival area below the arena. Remaining failures or untested critical rows block a production-ready claim.
